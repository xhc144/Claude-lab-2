**整块打标记，零散暴力**

## 问题：区间加，数 ≥ c 的个数

- `0:22` 两种操作：给 [l, r] 每个数加 x；询问 [l, r] 里有多少个数 ≥ c。
  - 板书：操作：区间加 x；询问区间内 ≥ c 的个数
- `0:30` 用线段树的话，结点要能回答“我这段里有几个数 ≥ c”，c 每次都不同，只能存整段排好序的数组——再加上区间加的标记，合并和下传都很难。
  - 板书：线段树：信息（有序数组）太大，带标记合并困难
- `0:45` 换一种思路：不切成 log n 层，只切一层。把数组分成若干块，每块长度 B。

## 分成 √n 块

- `0:57` 这里 n = 12，每块 4 个，共 3 块。每块额外维护两样东西：一个整块的加法标记 tag，以及块内元素排好序的副本。
  - 板书：每块：加法标记 tag + 块内元素的有序副本
- `1:09` 核心原则：整块的部分打标记，零散的部分暴力。一个区间最多覆盖两个零散的半块，中间都是整块。
  - 板书：整块：只动标记；零散：直接改元素

## 区间加

- `1:24` 例：给 [3, 10] 加 2。第 1 块只覆盖了 3、4 两个位置（零散），第 2 块整块被覆盖，第 3 块只覆盖 9、10（零散）。
- `1:36` 整块（第 2 块）：只把 tag 加 2。有序副本完全不用动——整块里每个数都加同样的数，相对大小顺序不变。
  - 板书：整块加：tag += x，有序副本不变（同加一个数，顺序不变）
- `1:47` 零散部分：直接改那几个元素，然后把这一块的有序副本重新排序，代价 O(B log B)。
- `1:57` 注意第 2 块的元素本身还是原值，真实值 = 元素 + tag。

## 询问 ≥ c 的个数

- `2:07` 询问 [2, 11] 中 ≥ 7 的个数。
- `2:11` 整块（第 2 块）：真实值 ≥ 7 ⇔ 存的值 ≥ 7 − tag = 5。在有序副本里二分，找到第一个 ≥ 5 的位置，后面的都满足。
  - 板书：整块：在有序副本里二分 ≥ c − tag，O(log B)
- `2:23` 第 2 块里有 2 个。零散部分（位置 2、3、4 和 9、10、11）逐个看真实值是否 ≥ 7。
- `2:32` 零散部分有 2 个，总共 4 个。
  - 板书：本例答案 4

## 块长取多少

- `2:39` 设块长 B，块数 n/B。一次操作：整块最多 n/B 个，每个 O(1)（加）或 O(log B)（二分）；零散最多 2B 个元素，加上重排 O(B log B)。
  - 板书：单次：整块 O((n/B)·log B) + 零散 O(B log B)
- `2:54` 一个随 B 增大而减小，一个随 B 增大而增大。两者相等时总和最小：B 取 √n 左右（考虑 log 因子可以略作调整）。
  - 板书：两部分平衡：B ≈ √n → 单次 O(√n · log n)
- `3:06` 分块的思想是“只分一层”：牺牲一点复杂度（√n 而不是 log n），换来信息不必能合并、标记不必能复合的自由。
  - 板书：分块：用 √n 换取“不需要可合并”的自由

## 手推 / 建模题

- `3:22` 先别急着看答案：按暂停，在纸上推一推。
- `3:48` 10¹⁸ → 10⁹ → 31622 → 177 → 13 → 3 → 1，最多 6 次就变成 1（或 0），之后再开平方也不变。
  - 板书：每个数最多被开 6 次平方就不再变化
- `3:57` 所以每块维护：块内和，以及一个标记“这块已经全是 0 或 1”。开平方时，整块如果已经全是 0/1 就直接跳过；否则逐个元素暴力开平方。
  - 板书：每块：和 + “全是 0/1”标记；已全是 0/1 的块直接跳过
- `4:12` 复杂度：每个元素一共最多被暴力处理 6 次，总共 O(6n)；每次操作还要扫过 O(n/B) 个块、处理 O(B) 个零散元素。分块不靠标记，靠的是“势能”。
