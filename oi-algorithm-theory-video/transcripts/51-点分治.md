## 把路径按“经过哪个点”分类

- `0:25` 这棵树有 10 个点，边长都是 1。问：距离 ≤ 3 的点对有几对？（答案是 32。）
  - 板书：问题：距离 ≤ K 的点对数（K = 3）
- `0:34` 任选一个点 c。所有路径分成两类：经过 c 的；完全在删掉 c 之后的某一个连通块里的。
  - 板书：路径 = 经过 c 的 + 完全在某个子树里的（递归）
- `0:44` 第二类正好是若干个规模更小的同类问题，递归去做。只要能高效地数出“经过 c 的”，就得到一个分治算法。
- `0:56` 可是 c 选不好，比如一条链总选端点，每次只少一个点，要递归 n 层。怎么选 c 才能让每层都变小很多？

## 选重心：每块不超过一半

- `1:11` 重心：删掉它之后，剩下的每个连通块都不超过 n/2 个点。
  - 板书：重心：删掉后每个连通块 ≤ n/2
- `1:18` 每个点旁边写的是“删掉它之后最大的连通块大小”。最小的那个点就是重心。
- `1:28` 点 3：删掉后剩下大小 3, 4, 2 的三块，都不超过 10/2 = 5。
- `1:35` 重心一定存在：从任一点出发，只要有一块超过一半，就往那一块走一步；那一块越走越小，最后一定停下。用一次 DFS 算子树大小就能找到。
  - 板书：找重心：DFS 求子树大小，O(n)
- `1:50` 每次都选重心，递归一层规模至少减半，所以递归深度不超过 log₂ n——每个点只会出现在 O(log n) 层里。
  - 板书：递归深度 ≤ log₂ n

## 数经过重心的点对

- `2:06` 以重心 3 为起点算出每个点的深度 d。经过 3 的路径 u—v 长度是 d(u) + d(v)，问题变成：有多少对 d(u) + d(v) ≤ 3？
  - 板书：经过 c：d(u) + d(v) ≤ K
- `2:18` 把深度排序，用双指针数满足条件的对数，得 27 对。（重心自己 d = 0，也参与配对：它和深度 ≤ 3 的点都算。）
  - 板书：排序 + 双指针：O(m log m)，这里 27 对
- `2:30` 但这样会多算：同一块里的两个点（同色），d(u) + d(v) ≤ 3，它们的真实路径并不经过 3。
- `2:40` 容斥：对每一块单独用同样的深度再数一遍（都是相对 3 的深度），共 5 对，减掉。
  - 板书：减去同一子树内的“假”点对（用同样的 d 再数一遍）
- `2:49` 经过 3 的点对 = 27 − 5 = 22。剩下的在三块里各自递归，每块再找自己的重心。
  - 板书：经过重心：27 − 5 = 22
- `2:58` 每一层所有块的大小加起来不超过 n，排序共 O(n log n)；一共 log n 层：总 O(n log² n)。
  - 板书：总复杂度 O(n log² n)
