## 问题：三维偏序

- `0:21` 8 个元素，每个有 (a, b, c)。对每个元素 i，求有多少个 j ≠ i 满足 aⱼ ≤ aᵢ、bⱼ ≤ bᵢ、cⱼ ≤ cᵢ。
  - 板书：求：aⱼ ≤ aᵢ, bⱼ ≤ bᵢ, cⱼ ≤ cᵢ 的 j 有几个
- `0:31` 两两比较是 O(n²)。先回忆少一维的情形：只有 (a, b) 时，按 a 排序后从前往后扫，用树状数组维护已经扫过的 b，每个元素查一次前缀和。
  - 板书：二维：按 a 排序 + 树状数组维护 b → O(n log n)
- `0:46` 三维多了一个条件。排序能消掉一维，树状数组能处理一维，还差一维——这一维交给分治。
  - 板书：三维：排序消一维 + 分治消一维 + 树状数组处理一维

## 按 a 排好，再对下标分治

- `1:00` 元素已经按 a 从小到大排好（这里 a 就是 1~8）。把序列从中间分成左右两半，分别递归处理，各自算好“半边内部”的贡献。
- `1:14` 剩下的只有“左半的 j 对右半的 i”的贡献。左半的 a 都 ≤ 右半的 a，所以 a 的条件自动满足！只需要数 bⱼ ≤ bᵢ 且 cⱼ ≤ cᵢ 的对数。
  - 板书：左半 → 右半：a 自动满足，只剩 (b, c) 二维问题
- `1:27` 这又是一个二维问题：把左右两半各自按 b 排序，像二维的做法一样扫描 b，树状数组维护 c。
  - 板书：左右各按 b 排序，扫描 b，树状数组按 c 计数

## 最顶层的那一次合并

- `1:42` 右半从 b 小到大依次处理。处理某个 i 之前，先把左半里所有 b ≤ bᵢ 的元素按 c 加进树状数组；然后查询 c ≤ cᵢ 的个数。
- `1:55` 扫描时 b 的指针只往右走，每个左半元素只加入一次，这一层的合并是 O(len · log n)。最后别忘了清空树状数组（只撤销加过的位置）。
  - 板书：一次合并 O(len log n)；树状数组用完要撤销

## 为什么每一对恰好算一次

- `2:13` 任取一对 j、i（按 a 排序后 j 在 i 前面）。递归的每一层，它们要么在同一半，要么被分到左右两半。
- `2:24` 例：#2 和 #3 在 [1,8]、[1,4] 里都在同一半，直到 [1,4] 分成 [1,2] 和 [3,4] 时才第一次分开——它们只在这一次合并中被统计。
  - 板书：每一对 (j, i) 恰在“第一次被分开”的那层合并中被统计一次
- `2:38` 一对元素第一次被分到两边，只发生在唯一的一层；之后它们在不同的子问题里，再也不会相遇。所以不重不漏。
- `2:50` 复杂度：每层合并总共 O(n log n)，一共 log n 层，O(n log² n)。
  - 板书：T(n) = 2T(n/2) + O(n log n) = O(n log² n)
- `2:58` 一个细节：完全相同的元素互相都要算上，但分治只算“左对右”。所以先把相同的三元组合并成一个，带上个数，再分别补上。
  - 板书：相同元素：先去重并记个数，最后补上彼此的贡献

## 手推 / 建模题

- `3:16` 先别急着看答案：按暂停，在纸上推一推。
- `3:42` (1) 一个点 j 对询问 i 有贡献，需要三个条件：j 发生在 i 之前（时间），xⱼ ≤ X，yⱼ ≤ Y。三维偏序：时间、x、y。
  - 板书：(1) 三维：时间、x、y
- `3:54` (2) 操作本来就按时间顺序给出，时间这一维已经排好，直接对操作序列分治。合并时只看“左半的加点操作”对“右半的询问操作”的贡献。
  - 板书：(2) 按时间分治；左半的加点 → 右半的询问；按 x 扫描、树状数组维护 y
- `4:09` 这就是 CDQ 最常见的用法：把“修改对后面询问的影响”离线成偏序问题，时间那一维由分治吃掉。
