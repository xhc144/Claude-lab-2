## 问题：最小支配集

- `0:25` 一棵树，每个点有一个费用。选一些点放保安，要求每个点要么被选，要么至少有一个邻居被选。总费用最少是多少？
  - 板书：每个点：自己被选，或有邻居被选（被“支配”）
  - 板书：求：被选点的总费用最小
- `0:37` 这叫最小支配集。在一般图上很难，在树上可以用树形 DP 在线性时间内解决。
- `0:46` 按习惯，先试试两个状态：u 选或不选。

## 两个状态为什么不够

- `0:56` 看最简单的例子：一条三个点的链，中间的点费用 1，两端各 5。显然只选中间的点，费用 1。
- `1:06` 如果规定“u 不选时，u 必须被它子树里的点支配”：叶子 a 不选的话，它的子树里没有别人，这个状态不合法，只好选 a。
  - 板书：尝试：g[u][1] 选 u；g[u][0] 不选 u 且被子树支配
- `1:19` 于是 a、c 都被迫选上，算出来至少 10，而正确答案是 1。漏掉的方案是：a 由它的父亲 b 来支配。
  - 板书：问题：叶子可以被父亲支配，子树内部不知道
- `1:30` 如果反过来允许“u 不选、也还没被支配”，那就必须告诉父亲：你一定要被选。这是另一种情况，需要单独的状态。
- `1:43` 所以“u 不选”要拆成两种：已经被某个儿子支配了，或者还在等父亲来支配。
  - 板书：“不选”拆成两种：被儿子支配 / 等父亲支配

## 三个状态

- `1:55` 站在父亲的角度问：关于子树 u，我需要知道什么？
  - 板书：f[u][0]：u 被选
  - 板书：f[u][1]：u 不选，已被某个儿子支配
  - 板书：f[u][2]：u 不选，还没被支配（父亲必须选）
  - 板书：三种情况下，子树里除 u 以外的点都必须已经被支配
- `2:01` 子树和外界唯一的联系是 u 和父亲之间的那条边。子树里除 u 以外的点都碰不到外面，所以它们必须在子树内部被支配。
- `2:14` 能影响外界、或被外界影响的只有 u 自己：u 选没选（影响父亲是否被支配），u 不选时是否已被支配（决定父亲是否必须选）。三个状态正好覆盖这些情况。
- `2:31` 转移。f[u][0]：u 被选，每个儿子三种状态都可以——儿子即使在“等父亲”，也被 u 支配了。
  - 板书：f[u][0] = 费用(u) + Σ min(f[v][0], f[v][1], f[v][2])
- `2:41` f[u][2]：u 不选、也没被支配，所以没有儿子被选；每个儿子也不能“等父亲”（父亲 u 没被选），只能是状态 1。
  - 板书：f[u][2] = Σ f[v][1]
- `2:54` f[u][1]：每个儿子取 min(f[v][0], f[v][1])，但至少要有一个儿子被选。
  - 板书：f[u][1] = Σ min(f[v][0], f[v][1])，至少一个儿子取 0
- `3:03` 技巧：先让每个儿子各取各的最小值。如果碰巧没有一个儿子选了状态 0，就挑 f[v][0] − f[v][1] 最小的那个儿子改成状态 0，补上这个差。
  - 板书：若都没取 0：加上 min(f[v][0] − f[v][1])

## 自底向上推一遍

- `3:22` 每个点旁边写上三元组 (f0, f1, f2)。叶子：选它花自己的费用；不选时没有儿子能支配它，f1 = ∞；f2 = 0（等父亲）。
  - 板书：(f0, f1, f2) = (选 u, 被儿子支配, 等父亲)
  - 板书：叶子：(费用, ∞, 0)
- `3:35` 点 2 的两个儿子都是叶子：f0 = 3 + 0 + 0 = 3；f1 要求至少选一个儿子，选费用 2 的点 4，得到 7；f2 = ∞ + ∞（叶子不能被儿子支配）。
- `3:48` 点 3 只有一个儿子 6，f[6] = (2, 7, ∞)。f0 = 6 + min(2, 7, ∞) = 8；f1 = min(2, 7) = 2，而且取的正是“6 被选”；f2 = f[6][1] = 7。
- `4:02` 根 1：f0 = 4 + min(3, 7, ∞) + min(8, 2, 7) = 4 + 3 + 2 = 9；f1 = min(3, 7) + min(8, 2) = 5，儿子 2 已取状态 0，满足要求；f2 = 7 + 2 = 9。
- `4:15` 根没有父亲，不能“等父亲”，所以答案是 min(f[1][0], f[1][1]) = 5。
  - 板书：答案 = min(f[根][0], f[根][1]) = 5（根不能取状态 2）
- `4:23` 顺着取到最小值的选择往回找，就是选点 2、6：每个点都被支配，总费用 5。
- `4:32` 每个点只算一次三元组，每条边只在父亲处用一次，总共 O(n)。

## 接口思维与变式

- `4:44` 这一集的方法可以概括为“接口思维”：子树和外界只通过 u 相连，状态就是 u 这个接口上所有可能的情况。
  - 板书：接口思维：状态 = 子树对外接口（u）上所有可能的情况
- `4:56` 拿它去看最大独立集：父亲只关心 u 选没选（选了的话父亲不能选），所以两个状态。
  - 板书：最大独立集：u 选 / 不选 → 两个状态
- `5:05` 如果改成“每个点要被距离 2 以内的被选点覆盖”，接口上就要说清楚：离 u 最近的被选点有多远，或者 u 还需要外面在多远之内提供覆盖——状态会更多。
  - 板书：距离 2 覆盖：要记“最近的被选点距离 / 还欠外面多远” → 更多状态
- `5:22` 状态多少不是记出来的，而是问出来的：父亲到底需要知道什么？

## 手推 / 建模题

- `5:33` 先别急着看答案：按暂停，在纸上推一推。
- `5:59` (1) 点覆盖里，u 和父亲之间那条边被覆盖，当且仅当 u 或父亲被选。所以 u 不选，就一定要求父亲被选——没有“已被儿子解决”这种可能。
  - 板书：(1) u 不选 ⇒ 父亲必选；不存在“被儿子解决”，两种情况足够
- `6:14` 支配集里，u 不选时，u 有可能已经被儿子支配，也可能还没有，所以要多一个状态。差别就在这里。
- `6:25` (2) u 不选时，要数它已经有几个被选的儿子：0 个、1 个、至少 2 个。父亲最多再补 1 个。
- `6:35` “0 个”的情况就算父亲被选也只有 1 个，不合法，直接丢掉。所以状态是：u 被选；u 不选且已有 ≥2 个儿子被选；u 不选且恰有 1 个儿子被选（父亲必须选）。
  - 板书：(2) 选 u / 不选且 ≥2 个儿子被选 / 不选且恰 1 个（等父亲）
- `6:51` 合并儿子时要记“已经有几个儿子被选（0、1、≥2）”，像一个很小的背包。
