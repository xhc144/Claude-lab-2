## 从一个区间挪到相邻区间

- `0:21` 询问：[l, r] 里有多少种不同的数。不强制在线：可以先把所有询问读进来，按任意顺序回答。
  - 板书：询问 [l, r] 中不同数的个数；离线（可以重排询问）
- `0:32` 关键观察：如果已经知道 [l, r] 的答案（并记着每个数出现了几次 cnt），那么扩展或收缩一格只要 O(1)。
  - 板书：[l, r] → [l, r±1] 或 [l±1, r]：O(1) 更新
- `0:44` 加入一个数 x：cnt[x] 从 0 变成 1 时，种类数 +1。删掉一个数：cnt[x] 从 1 变成 0 时，种类数 −1。
- `0:54` 于是回答一串询问，就是让两个指针 l、r 依次挪到每个询问的位置，代价 = 指针移动的总距离。
  - 板书：总代价 = 两个指针移动的总步数
- `1:05` 按读入顺序处理，最坏每次都要从一头挪到另一头，O(n·q)。能不能排个序，让总移动量变小？

## 把询问画成平面上的点

- `1:21` 把每个询问 (l, r) 看成平面上的一个点。从一个询问到下一个，指针移动的步数就是两点之间的“曼哈顿距离” |Δl| + |Δr|。
- `1:35` 问题变成：给这些点排一个访问顺序，让路径总长尽量短。最优顺序很难求，但莫队给了一个简单又够好的顺序。

## 莫队的顺序：先按块，再按右端点

- `1:52` 把 l 按块分组（块长 B，这里 B = 4）：先按 l 所在的块排序，同一块里按 r 从小到大排序。
  - 板书：排序：先按 l 所在的块，同块内按 r 递增
- `2:01` 在同一个竖条（同一块）里，r 只往上走；l 在块内来回晃，但每次最多晃 B 步。
- `2:11` 为什么这样就快？分开数两个指针的移动：
  - 板书：r：每块内单调递增，每块 O(n)，共 n/B 块 → O(n²/B)
  - 板书：l：每个询问在块内移动 ≤ B，跨块 O(n) 共 n/B 次 → O(qB + n)
- `2:16` r 在每一块里单调，最多走 n 步；一共 n/B 块，合计 O(n²/B)。l 每个询问最多在块内挪 B 步，合计 O(qB)。
- `2:28` 取 B = n/√q（n、q 同阶时就是 √n），总移动量 O(n√q)。n = q = 10⁵ 时大约 3×10⁷ 次 O(1) 的更新。
  - 板书：B ≈ n/√q → 总 O(n√q)；n、q 同阶即 O(n√n)
- `2:38` 小优化：奇数块里 r 从小到大，偶数块里从大到小（奇偶排序），r 不用每到新的一块都从头跑，常数能小不少。

## 什么时候能用莫队

- `2:54` 条件一：离线——必须能先读入所有询问再重排。题目强制在线（下一个询问依赖上一个答案）时不能用。
  - 板书：① 离线
- `3:06` 条件二：区间伸缩一格的更新要快。不同数的个数、出现次数的平方和（小 Z 的袜子）都是 O(1)。
  - 板书：② 伸缩一格的代价小（通常 O(1)）
- `3:17` 条件三：没有修改。带修改时可以给询问再加一维“时间”，变成三个指针（带修莫队），复杂度 O(n^(5/3))。
  - 板书：③ 无修改（有修改：带修莫队，加时间维）
- `3:29` 莫队的本质：答案只依赖区间，而相邻区间转移便宜——于是把“很多次重新计算”变成“一条尽量短的路径”。

## 手推 / 建模题

- `3:45` 先别急着看答案：按暂停，在纸上推一推。
- `4:11` (1) 直接按 l 排序：l 只往右走，但相邻两个询问的 r 可以忽大忽小，每次都可能跳 O(n)，总共 O(n·q)。
  - 板书：(1) 只按 l 排：r 来回跳，O(nq)
- `4:22` 分块之后，同一块里的询问按 r 排好，r 在块内单调——用 l 的“粗略”顺序换来 r 的单调性。
  - 板书：分块：l 粗排、r 在块内单调 → 两个指针都受控
- `4:32` (2) 总移动量不变，仍是 O(n√q)，每步多一个 log：O(n√q · log n)。块长的平衡点不变，因为两边都乘上了同一个 log。
  - 板书：(2) O(n√q · log n)；块长不变（两边同乘 log）
