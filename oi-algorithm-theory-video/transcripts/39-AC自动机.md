## 把模式串放进一棵 Trie

- `0:27` 模式串 he、she、his、hers 插入 Trie：每个结点代表一个前缀，结点里写的就是这个前缀。
  - 板书：Trie 的结点 = 所有模式串的所有前缀
- `0:38` 黄框的结点是某个模式串的结尾。在 Trie 上沿着文本走，就能同时和所有模式串比较——问题还是失配：走不下去时该去哪？
  - 板书：单个模式串失配看 π；多个模式串失配看 fail

## fail：最长的、在 Trie 里的真后缀

- `0:56` 类比 KMP：对结点 u（代表串 str(u)），fail(u) 指向 str(u) 的最长真后缀里、在 Trie 中出现的那一个。
  - 板书：fail(u) = str(u) 的真后缀中，在 Trie 里最长的那个
- `1:07` 例：she 的真后缀有 he、e 和空串。he 在 Trie 里，而且最长，所以 fail(she) = he。
- `1:17` 这和 KMP 的 π 是同一个想法：已经匹配上的部分里，“最长的、还能继续往下匹配”的后缀。单个模式串时，Trie 是一条链，fail 就是 π。
  - 板书：单个模式串时 fail 就是 π

## 按 BFS 顺序构造 fail

- `1:35` 深度为 1 的结点，fail 都指向根。其余结点 v（父亲 u，边上字符 c）：str(v) 的后缀去掉最后的 c，就是 str(u) 的后缀。
  - 板书：v = u 的 c 儿子：沿 fail(u) 的链找第一个有 c 儿子的结点 f，fail(v) = f 的 c 儿子
- `1:48` 所以从 fail(u) 出发沿 fail 链往上找，第一个有 c 儿子的结点 f，fail(v) 就是 f 的 c 儿子；找不到就指向根。
- `2:00` 链上的结点都比 v 浅，按 BFS（一层一层）的顺序处理，用到的 fail 都已经算好了。
  - 板书：BFS 顺序：用到的 fail 都更浅，已算好
- `2:09` sh：父亲是 s，从 fail(s) 出发找 h 儿子，依次看 ε，找到 h，所以 fail = h。
- `2:18` his：父亲是 hi，从 fail(hi) 出发找 s 儿子，依次看 ε，找到 s，所以 fail = s。
- `2:27` hers：父亲是 her，从 fail(her) 出发找 s 儿子，依次看 ε，找到 s，所以 fail = s。
- `2:36` 没画箭头的结点，fail 都指向根。每个结点沿链往上找的总步数，和 KMP 一样可以用深度做势能分析，整体是线性的（乘字符集大小）。
  - 板书：构造 O(Σ|Pᵢ| · |Σ|)，与 KMP 同样的势能论证

## 扫描文本：每一步都只沿边走

- `2:56` 再进一步：把“失配就沿 fail 跳”预先算进转移里。trans(u, c)：u 有 c 儿子就走过去，否则等于 trans(fail(u), c)。
  - 板书：trans(u, c) = u 的 c 儿子；没有则 = trans(fail(u), c)
- `3:09` 按 BFS 顺序补全每个结点、每个字符的转移（Trie 图），匹配时每读一个字符只走一步，不再有 while 循环。
- `3:21` 到达 she：它是模式串，报告 she。沿 fail 链往上，he 也是模式串——he 也在这里结尾！
  - 板书：到达 u 时，fail 链上所有的模式串结尾都在这里出现
- `3:31` 读到 r：she 没有 r 儿子。补全的转移已经替我们沿 fail 跳到 he，再走到 her——一步到位。
- `3:41` 一遍扫描，三个出现全部找到。注意报告时要沿 fail 链收集——下一集会看到，这条链可以变成一棵树来批量处理。
