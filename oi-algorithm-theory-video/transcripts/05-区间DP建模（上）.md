## 问题：石子合并

- `0:21` 一排 4 堆石子：2、3、1、3。每次只能合并相邻的两堆，代价是合并后这一堆的石子数。
  - 板书：每次合并相邻两堆，代价 = 新堆大小
  - 板书：求：合成一堆的最小总代价
- `0:31` 最自然的贪心：每次挑合并代价最小的相邻两堆。
  - 板书：贪心：每次合并和最小的相邻两堆？
- `0:38` 贪心总代价 19。但先合并 2、3，再合并 1、3，最后合并 5 和 4，总代价是 5 + 4 + 9 = 18。
  - 板书：贪心 19 > 最优 18
- `0:48` 贪心第一步把 3 和 1 合成 4，看着便宜，却让中间出现了一个大堆，后面每次合并都要再付一遍它。
- `0:59` 补充：如果任意两堆都能合并（不要求相邻），“每次合并最小的两堆”就是最优的哈夫曼编码。正是“相邻”这个限制让贪心失效。
  - 板书：不要求相邻 → 哈夫曼贪心正确；相邻限制使贪心失效

## 枚举最后一步

- `1:17` 合并的顺序有很多种。怎样把它们分类，变成子问题？
- `1:24` 看最后一次合并：它把两堆合成一堆。这两堆各自是什么？
- `1:31` 因为每次只合并相邻的，任何时刻每一堆都是原来连续的一段。所以最后一次合并的，一定是 [1, k] 和 [k+1, 4] 这样的两段。
  - 板书：任何时刻，每一堆都是原序列的连续一段
- `1:44` 在最后一次合并之前，左段和右段完全独立：左边怎么合并不影响右边。所以两边各自取最优就行。
  - 板书：f[l][r]：把 [l, r] 合成一堆的最小代价
  - 板书：f[l][r] = min_k ( f[l][k] + f[k+1][r] ) + sum(l..r)
- `1:56` 最后一次合并的代价是 [l, r] 全部石子数 sum(l..r)，和 k 无关，所以可以提到 min 外面。
- `2:06` 为什么不漏不重？每一种合并方案都有唯一的“最后一次合并”，也就有唯一的分界点 k。按 k 分类，每个方案恰好落在一类里。
  - 板书：按最后一次合并的分界点 k 分类：不重不漏
- `2:19` 如果换成枚举“第一次合并”呢？合并了第 i、i+1 堆之后，剩下的东西不再是“一段原始石子”，子问题的形状变了，状态描述不了。
  - 板书：枚举第一步：剩下的不是同类子问题 ✗
- `2:34` 这就是区间 DP 的基本思路：选一个“最后一步”，让它把区间切成几个同类型的更小区间。

## 按长度填表

- `2:48` f[l][r] 依赖更短的区间，所以按长度从小到大填：先长度 1（都是 0），再长度 2、3、4。
  - 板书：顺序：区间长度从小到大
- `2:59` 最后算 f[1][4]。三个分界点：
- `3:05` 最小的是 k = 2，再加上全部石子数 9，得到 f[1][4] = 18。
- `3:12` 状态 O(n²) 个，每个枚举 O(n) 个分界点，总共 O(n³)。n 到几百没有问题。
  - 板书：O(n²) 个状态 × O(n) 分界点 = O(n³)
- `3:21` （满足四边形不等式时最优分界点有单调性，可以优化到 O(n²)，这里不展开。）

## 环形：倍长成链

- `3:33` 如果石子围成一圈，第一堆和最后一堆也算相邻，怎么办？
- `3:41` 观察：n 堆合成一堆要合并 n − 1 次，而环上有 n 处“相邻缝隙”。每次合并跨过一处缝隙，所以总有一处缝隙从来没被跨过。
  - 板书：n−1 次合并、n 处缝隙 → 至少一处缝隙从没被跨过
- `3:54` 在那处缝隙把环剪开，就得到一条链，问题变回了直线版。只是我们不知道该在哪里剪，所以枚举剪开的位置。
  - 板书：在没被跨过的缝隙剪开 → 一条链；枚举剪开位置
- `4:06` 把数组复制一遍接在后面（长度 2n−1），从第 i 堆开始、长度为 n 的每一段，正好对应一种剪法。
  - 板书：倍长：a[1..2n−1]，答案 = min f[i][i+n−1]
- `4:17` 在倍长的数组上只做一次区间 DP（长度不超过 n），答案取 min f[i][i+n−1]。复杂度仍是 O(n³)，而不是剪 n 次各做一遍。

## 手推 / 建模题

- `4:34` 先别急着看答案：按暂停，在纸上推一推。
- `5:00` (1) 最后一次合并 [l, k] 与 [k+1, r]，代价是 sum(l..k) × sum(k+1..r)，现在和 k 有关了，要放进 min 里面。
  - 板书：f[l][r] = min_k ( f[l][k] + f[k+1][r] + S(l,k) × S(k+1,r) )
- `5:11` (2) 换个角度数代价：把每堆石子拆成一颗颗石子。合并 a 和 b 的代价 a × b，恰好是“一颗来自左堆、一颗来自右堆”的石子对数。
- `5:25` 任意两颗石子，恰好在它们第一次进入同一堆时被数一次。所以无论怎样合并，总代价都等于所有 aᵢ × aⱼ（i < j）之和。
  - 板书：总代价 = Σ aᵢaⱼ（i < j），与合并顺序无关！
- `5:38` 例如 2、3、1、3：任何顺序的总代价都是 29。这和上一集“点对只在 LCA 处被数一次”是同一个想法。
- `5:50` 教训：写 DP 之前，先看看代价有没有更简单的结构。
