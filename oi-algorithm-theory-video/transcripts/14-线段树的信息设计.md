## 问题：区间最大子段和

- `0:23` 一个数组，支持两种操作：修改一个数；询问区间 [l, r] 里和最大的连续子段（最大子段和）。
  - 板书：操作：单点修改；询问 [l, r] 的最大子段和
- `0:34` 例如整个数组的最大子段是 4、−1、2，和为 5。每次询问都扫一遍是 O(n)，询问多了就慢。
- `0:44` 线段树：每个结点管一段区间，存这段区间的“信息”。询问时把 [l, r] 拆成 O(log n) 个结点，把它们的信息依次合并。
  - 板书：线段树：询问 = 合并 O(log n) 个结点的信息
- `0:57` 所以关键问题只有一个：结点里存什么，才能只用两个儿子的信息算出父亲的信息？
  - 板书：关键：信息必须“可合并”——父亲 = 合并(左儿子, 右儿子)

## 只存最大子段和，够吗

- `1:11` 假设每个结点只存“最大子段和”。左半 [1, 4] 的最大子段和是 4，右半 [5, 8] 是 3。
- `1:21` 可整体的答案是 5：子段 4、−1、2 跨过了中点。只知道两边各自的最大值，算不出跨过中点的子段。
  - 板书：只存“最大子段和”：跨中点的子段算不出 ✗
- `1:32` 跨过中点的子段 = 左半的一个后缀 + 右半的一个前缀。要它最大，就取左半的最大后缀（3）加右半的最大前缀（2）。
  - 板书：跨中点的最大值 = 左.最大后缀 + 右.最大前缀
- `1:45` 于是结点还要存“最大前缀和”和“最大后缀和”。那么父亲的最大前缀怎么算？
- `1:54` 父亲的前缀要么完全在左半（左.前缀），要么吃掉整个左半再延伸到右半（左.总和 + 右.前缀）。又需要“总和”。
  - 板书：父.前缀 = max(左.前缀, 左.和 + 右.前缀) → 还需要“和”
- `2:06` “和”自己合并很简单：两边相加。到这里，四个量互相够用了：算父亲的任何一个量，只用到儿子的这四个量。
  - 板书：(和, 前缀, 后缀, 最大)：合并只用到这四个量 → 封闭

## 合并公式与为什么够

  - 板书：和 = 左.和 + 右.和
  - 板书：前 = max(左.前, 左.和 + 右.前)
  - 板书：后 = max(右.后, 右.和 + 左.后)
  - 板书：最 = max(左.最, 右.最, 左.后 + 右.前)
- `2:25` 为什么“最”的公式不会漏？父亲区间里的任意一个子段，只有三种可能：完全在左半、完全在右半、跨过中点。
- `2:37` 前两种的最大值是左.最、右.最；第三种拆成“左边的某个后缀 + 右边的某个前缀”，两部分可以分别取最大，所以是左.后 + 右.前。
- `2:51` 三种情况覆盖了全部子段、互不遗漏，取最大就对了。前缀、后缀的公式也是同样的分类。
- `3:02` 这就是设计结点信息的方法：先写出想要的量，看合并时缺什么，就补什么，直到这组量对合并封闭。

## 建树与查询

- `3:17` 叶子的四个量都是它本身的值。从下往上，每个结点用公式合并两个儿子：
- `3:26` 根上的“最”是 5，就是整个数组的答案。
- `3:32` 询问 [2, 7]：拆成 [2]、[3,4]、[5,6]、[7] 这 4 个结点，从左到右依次合并。
- `3:41` 结果的“最”是 5，和直接枚举 [2, 7] 的所有子段得到的一样。注意合并要按从左到右的顺序：这个合并不满足交换律。
- `3:53` 修改一个数时，只要重新计算它到根路径上的 log n 个结点。询问、修改都是 O(log n)。

## 反例：区间众数

- `4:07` 不是所有信息都能这样设计。比如“区间众数”（出现次数最多的数）。
- `4:15` 左半的众数是 1，右半的众数是 3。可合在一起，2 出现了 4 次，众数是 2——它在哪一半都不是众数。
  - 板书：众数：合并后的众数可能在两半都不是众数 ✗
- `4:26` 想要能合并，就得存下每个数的出现次数，信息量和区间长度一样大，失去了线段树的意义。众数要用别的方法（如第 31 集的分块）。
  - 板书：可合并的前提：用固定几个量就能封闭

## 手推 / 建模题

- `4:44` 先别急着看答案：按暂停，在纸上推一推。
- `5:10` 仿照最大子段和：跨过中点的上升段 = 左半的“最长上升后缀” + 右半的“最长上升前缀”。
- `5:20` 但能不能接上，要看左半最后一个数是否小于右半第一个数。所以还要存区间的首元素和尾元素。
  - 板书：存：长度 len、首元素 first、尾元素 last、上升前缀 pre、上升后缀 suf、最长 best
  - 板书：best = max(左.best, 右.best, 左.last < 右.first ? 左.suf + 右.pre : 0)
- `5:31` 前缀也要分情况：如果左半整体就是上升的（左.pre = 左.len）并且能接上，父.pre = 左.len + 右.pre，否则就是左.pre。
  - 板书：pre = (左.pre = 左.len 且 左.last < 右.first) ? 左.len + 右.pre : 左.pre
- `5:44` 又是同样的步骤：写出想要的量 → 看合并缺什么（边界元素、整体是否上升）→ 补上，直到封闭。
