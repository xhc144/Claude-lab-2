## 问题：最短哈密顿路

- `0:22` 4 个城市，两两之间的距离标在边上。从城市 0 出发，每个城市恰好经过一次，路线最短是多少？（终点任意）
  - 板书：从 0 出发，经过每个城市恰好一次，求最短路线
- `0:34` 枚举所有顺序要 (n−1)! 种。n = 20 时约 1.2×10¹⁷，不可能。要找能合并的东西。
  - 板书：枚举顺序：(n−1)!，n = 20 时 ≈ 1.2×10¹⁷

## 状态：走过的集合 + 现在的位置

- `0:48` 换成 5 个城市来看。走到一半时，要决定接下来怎么走，需要知道过去的什么？
- `0:57` 两样东西：现在在哪个城市（下一步的距离从这里算），以及哪些城市已经去过（不能再去，剩下的必须去）。
  - 板书：未来只取决于：当前城市 v + 已访问集合 S
- `1:09` 先看可以合并的：0→1→2→3 和 0→2→1→3，都停在 3，都去过 {0, 1, 2, 3}。剩下的都只有城市 4，未来完全一样。
- `1:21` 所以只要留下两条里较短的那条。经过的顺序不需要进状态。
  - 板书：顺序不进状态：同集合、同终点的路线只留最短的
- `1:29` 那能不能只记“去过几个城市”，不记是哪几个？看 0→1→2 和 0→3→2：都停在 2，都去过 3 个城市。
- `1:40` 剩下要去的城市不同，未来不同，不能合并。所以只记个数不够，必须记住是哪一个集合。
  - 板书：只记个数 ✗：剩下的城市不同，未来不同
  - 板书：f[S][v]：从 0 出发，恰好走过集合 S，停在 v 的最短长度

## 用二进制表示集合

- `1:53` 集合怎么当数组下标？n 个城市，每个城市在或不在，正好是 n 位二进制数。第 i 位是 1 就表示城市 i 在集合里。
  - 板书：集合 S ↔ n 位二进制数：第 i 位 = 城市 i 在不在
- `2:05` 于是 f[S][v] 就是普通的二维数组 f[0..2ⁿ−1][0..n−1]。判断 u 在不在 S 里、把 u 加进 S，都是一次位运算。
  - 板书：u 在 S 中：S 的第 u 位为 1；加入 u：S | (1 << u)
- `2:17` 转移：从 f[S][v] 出发，走到一个没去过的城市 u：f[S ∪ {u}][u] ← f[S][v] + d(v, u)。
  - 板书：f[S∪{u}][u] = min( f[S][v] + d(v, u) )，u ∉ S
- `2:27` 按什么顺序算？把 u 加进 S，二进制数一定变大。所以只要按 S 从小到大的顺序算，用到的状态都已经算好了。
  - 板书：顺序：S 从小到大（加一个元素，数值一定变大）

## 推一遍

- `2:43` 表的每一行是一个包含城市 0 的集合，按数值从小到大排；暗格表示 v 不在 S 里，没有意义。
- `2:53` 起点：f[0001][0] = 0。然后一行一行往下算。
- `2:59` 例：f[0111][2]，走过 {0, 1, 2}、停在 2。上一步的集合是 0011，只能停在 1（停在 0 就说明 1 没去过），所以 f[0111][2] = f[0011][1] + d(1, 2) = 2 + 3 = 5。
- `3:16` 最后一行 1111 是走遍所有城市的结果。取最小值：停在 3，长度 6。
- `3:24` 沿着每一步的最优来源倒推回去，得到路线 0 → 1 → 2 → 3。

## 复杂度与适用范围

- `3:34` 状态有 2ⁿ × n 个，每个状态向外枚举 n 个城市，总共 O(2ⁿ · n²)。
  - 板书：O(2ⁿ × n²)　n = 20：约 4×10⁸ 次简单运算
- `3:41` 红色是枚举顺序，青色是状压 DP（纵轴是 10 的几次方）。n = 20 时差了大约 8 个数量级。
- `3:51` 但 2ⁿ 本身还是指数：n 到 30 左右就不行了。状压 DP 适用于“集合元素很少”的问题，题目里 n ≤ 20 往往就是提示。
  - 板书：适用：集合的元素个数很小（n ≤ 20 左右）

## 手推 / 建模题

- `4:07` 先别急着看答案：按暂停，在纸上推一推。
- `4:33` 按人的编号依次分配：第 1 个人、第 2 个人……状态 f[S]：前 |S| 个人已经分配完，用掉的工作集合是 S。
  - 板书：f[S]：前 |S| 个人做了集合 S 里的工作，最小代价
- `4:44` “现在轮到谁”就是 |S| + 1，由 S 中 1 的个数决定，不用单独记——这又是第 2 集里的“隐含维度”。
  - 板书：轮到第 |S|+1 个人：由 S 决定 → 隐含维度
- `4:55` 转移：第 |S|+1 个人选一项没被选的工作 j：f[S ∪ {j}] ← f[S] + c[|S|+1][j]。状态 2ⁿ 个，每个 n 个转移，O(2ⁿ · n)。
  - 板书：f[S ∪ {j}] ← f[S] + c[|S|+1][j]　O(2ⁿ × n)
- `5:08` 对比哈密顿路：那里“停在哪”影响下一步的代价，所以要记 v；这里下一步的代价只和“轮到谁”有关，而它已经藏在 S 里了。
